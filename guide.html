02

One-time setup

~2 minutes

One install at the root, one .env file at the root, no per-folder ceremony. After this you can run any step with make step-N.

Before you start

Python 3.11+ & uv Check with python3 --version. The workspace pins requires-python = ">=3.11". Install uv with curl -LsSf https://astral.sh/uv/install.sh | sh — it manages the venv and runs every step.
An Anthropic API key Create one at console.anthropic.com → API Keys. The steps make real API calls, so add a little billing credit — a dollar or two covers the whole workshop.
No separate CLI install The Agent SDK is a standalone package: claude-agent-sdk ships a bundled Claude Code binary and uses it automatically — no npm install -g. Node 20+ is needed only for the npx filesystem MCP server in steps 2, 5 and 6.

Three commands

  1. git clone <repo> && cd gritai-agentsdk-python-course
  2. cp .env.example .env — paste your ANTHROPIC_API_KEY
  3. uv sync --all-packages — installs all 14 workspace members

Then any time

  1. make step-1 — smallest agent loop
  2. make step-10 — the capstone
  3. make typecheck — mypy across the workspace

Your .env

# Required for every Claude step ANTHROPIC_API_KEY=sk-ant-... # Optional — only step 11 (Ollama) # OLLAMA_MODEL=llama3.3

Why no python-dotenv?

uv has --env-file built in. Every make step-N target runs uv run --env-file=.env ..., which loads the root .env into os.environ before Python starts — so the root .env is the single source of truth, with no load_dotenv() line in any source file.

03

Five concepts you'll use

5 ideas

Everything the SDK adds is a variation on one of these. Once you see how they compose, the capstone reads like ordinary code.

MCP servers

A standard way to attach tools to a model. Use an external one (e.g. the filesystem server), or write your own in Python as an in-process server with create_sdk_mcp_server.

step 2 · step 3

Built-in tools

Read, Write, Edit, Bash, Glob, Grep — the same toolset Claude Code uses, no MCP needed for local file work.

step 2b

Skills

Plain-Markdown files in .claude/skills/. The agent auto-discovers them and pulls one in when its description matches the task — no code change to swap behaviour.

step 4

Hooks & permissions

Intercept every tool call before it runs. PreToolUse hooks log, deny, or rewrite; can_use_tool asks a human; permission_mode picks the default policy.

step 8 · step 9

Subagents

Decompose a job into specialists with their own prompt and tool whitelist. The main agent dispatches to them with the built-in Task tool.

0raw api
The raw Anthropic SDK

One messages.create() call. No Agent SDK, no tools — just the primitive everything else is built on.

foundation anthropic messages.create
▸
Run it
$ make step-0
The core call
from anthropic import AsyncAnthropic client = AsyncAnthropic() response = await client.messages.create( model="claude-sonnet-4-6", max_tokens=1024, messages=[{"role": "user", "content": "Explain what an AI agent is in three sentences."}], )
What you'll see

Three sentences of plain text, then the token usage and stop reason. No loop, no tool calls — just one round-trip.

Try this

Change the prompt to ask Claude to run a tool ("read this file"). It will describe running one but can't actually act — that's exactly the gap the Agent SDK closes in step 1.

1loop
Smallest possible Agent SDK program

One query() call, an async iterable of messages, no tools. The loop is the SDK; the SDK is the loop.

foundation query() async for
▸
Run it
$ make step-1
The whole program
from claude_agent_sdk import (AssistantMessage, ClaudeAgentOptions, ResultMessage, TextBlock, query) options = ClaudeAgentOptions(model="claude-sonnet-4-6") async for message in query(prompt="Explain what an AI agent is.", options=options): if isinstance(message, AssistantMessage): for block in message.content: if isinstance(block, TextBlock): print(block.text, end="") elif isinstance(message, ResultMessage): print(f"Cost: ${message.total_cost_usd:.6f}")
Key idea

The stream emits typed messages: a SystemMessage (init), one or more AssistantMessage with content blocks, and a final ResultMessage with cost. Check them with isinstance(). With no tools allowed you'll only ever see TextBlocks — tool-use blocks show up from step 2.

Heads-up

In Python the content is right on message.content — no nested .message.content wrapper like the TypeScript SDK has.

2mcp ext
External MCP — the filesystem server

Plug in an external stdio MCP server (the official filesystem one) and let the agent write a haiku to a sandbox folder.

mcp mcp_servers allowed_tools
▸
Run it
$ make step-2
Key shape
mcp_servers={ "fs": { # the key becomes the tool prefix: mcp__fs__* "type": "stdio", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", str(SANDBOX_DIR)], }, }, allowed_tools=[ "mcp__fs__write_file", "mcp__fs__read_text_file", # newer name the server now prefers ],
The #1 footgun

MCP tools are denied by default. You must whitelist them. Wildcards work (mcp__fs__*); explicit names give you least-privilege.

Heads-up

This is the one place a step needs Node on your PATH — npx downloads and launches the filesystem server. The Agent SDK itself doesn't need it.

2bbuilt-in
Built-in tools — no MCP needed

The SDK ships Read, Write, Edit, Bash, Glob, Grep. Reach for MCP for external services; use built-ins for local files.

mcp built-in tools add_dirs
▸
Run it
$ make step-2b
The change from step 2
options = ClaudeAgentOptions( model="claude-sonnet-4-6", allowed_tools=["Read", "Write", "Bash"], # bare names, no mcp__ prefix add_dirs=[SANDBOX_DIR], # grants file-tool access outside cwd )
Read the small print

allowed_tools is an auto-approve list, not an availability whitelist. An agent with allowed_tools=["Read","Write"] can still call Bash at runtime — to actually remove a tool, use disallowed_tools. The capstone (step 10) uses both.

Try this

Edit the prompt to ask the agent to run ls via Bash first. Then add disallowed_tools=["Bash"] and rerun — it will refuse and pick a different approach.

3mcp own
A custom MCP server in Python

Define your own tools with the @tool decorator + create_sdk_mcp_server. Canned weather data here — the next step turns this into a real API.

mcp @tool create_sdk_mcp_server
▸
Run it
$ make step-3
Defining a tool
from claude_agent_sdk import create_sdk_mcp_server, tool @tool("getWeather", "Get the current weather for a city.", {"city": str}) async def get_weather(args: dict) -> dict: city = args["city"] w = FAKE_WEATHER.get(city, {"description": "Sunny", "tempC": 22}) return {"content": [{"type": "text", "text": f"{city}: {w['description']}, {w['tempC']}°C"}]} weather_server = create_sdk_mcp_server(name="weather", version="1.0.0", tools=[get_weather, get_forecast])
The big lever

The description string is what the model reads to decide when to call the tool. Write it well — this is the single biggest lever on tool-use quality.

Heads-up

The third arg is the input schema in shorthand form — a dict of {"field": type}. It can't express min/max, so clamp values in code. Mount the server with mcp_servers={"weather": weather_server}.

3breal api
Same tool, calling a real API

The handler now hits Open-Meteo over httpx. No API key, no fuss — and the agent gets actual weather.

mcp httpx open-meteo
▸
Run it
$ make step-3b
The payoff

The agent doesn't know or care that the tool changed. From its point of view, "getWeather" is the same tool — except now it returns real, current data.

The pattern
import httpx async def get_weather(args: dict) -> dict: async with httpx.AsyncClient() as client: place = await geocode(client, args["city"]) if place is None: return friendly(f"Couldn't find \"{args['city']}\".") resp = await client.get("https://api.open-meteo.com/v1/forecast", params={"latitude": place["latitude"], "longitude": place["longitude"], "current": "temperature_2m,weather_code"}, timeout=10.0) return {"content": [{"type": "text", "text": format(resp.json())}]}

When a fetch fails, return a friendly message — the agent reads it as a tool result and recovers gracefully.

Try this

Add a third tool — getAirQuality, also via Open-Meteo. Add it to allowed_tools and watch the agent pick the right one for the question.

4skills
Skills — Markdown files that change behaviour

A skill is a folder under .claude/skills/<name>/SKILL.md. The agent reads the description and pulls the body in when the task matches.

skills setting_sources .claude/skills/
▸
Run it
$ make step-4
The whole "code" change
options = ClaudeAgentOptions( model="claude-sonnet-4-6", setting_sources=["project"], # scope discovery to this folder )
Read the small print

The SDK default loads all sources (user + project + local) — not empty. So .claude/skills/ already loads even if you omit setting_sources. Passing ["project"] scopes discovery to this folder (reproducible workshop runs); passing [] is the SDK's isolation mode and is the real way to disable skills.

Try this

Set setting_sources=[] and rerun — the agent emits unstructured prose with no error. Then put it back to ["project"] and watch the skill kick in and produce the templated output.

5repl
Multi-turn terminal REPL

Type, the agent answers, type again — keeping context. Two approaches in the same folder: resume per turn, or one query alive over a stream.

i/o resume streaming-input
▸
Run it
$ make step-5
$ make step-5-streaming
The resume pattern
from dataclasses import replace session_id: str | None = None while True: user_input = await prompt("you > ") turn_options = replace(base_options, resume=session_id) if session_id else base_options async for message in query(prompt=user_input, options=turn_options): if isinstance(message, SystemMessage) and message.subtype == "init": session_id = message.data.get("session_id") # ...print text...
About the agent setup

The agent itself (system prompt, allowed tools) lives in agent.py. The streaming-input variant (main_streaming.py) keeps one query() alive and feeds it an async generator of user-message dicts instead of calling query() per turn.

Heads-up

ClaudeAgentOptions is a dataclass — use dataclasses.replace() to set resume for a turn rather than mutating the shared instance.

6web
Same agent, behind a FastAPI UI

SSE streaming with token-by-token deltas via include_partial_messages. The agent code didn't change — just the I/O surface.

i/o FastAPI SSE include_partial_messages
▸
Run it
$ make step-6

Opens at http://localhost:8000.

The streaming bit
base_options.include_partial_messages = True # raw content_block_delta events async for msg in query(prompt=message, options=base_options): if isinstance(msg, StreamEvent): ev = msg.event if ev.get("type") == "content_block_delta": delta = ev.get("delta") or {} if delta.get("type") == "text_delta": yield _sse({"type": "text", "text": delta.get("text", "")})
The shape of it

The endpoint is a POST /api/chat returning a StreamingResponse with media_type="text/event-stream". _sse(payload) just formats f"data: {json.dumps(payload)}\n\n".

Try this

Open the Network panel and watch the SSE stream. Each data: {"type": "text", "text": "..."} line is one token-ish chunk arriving from Claude.

7subagents
Delegate to specialist subagents

A coordinator agent dispatches to a code-reviewer and a test-planner via the built-in Task tool. Each subagent has its own prompt and toolset.

control agents AgentDefinition Task tool
▸
Run it
$ make step-7
The shape
from claude_agent_sdk import AgentDefinition options = ClaudeAgentOptions( model="claude-sonnet-4-6", allowed_tools=["Read", "Task"], # Task = how the coordinator dispatches agents={ "code-reviewer": AgentDefinition( description="Reviews code for bugs, security, and code smells.", prompt="You are a senior code reviewer. ...", tools=["Read", "Grep"], ), "test-planner": AgentDefinition(description="...", prompt="...", tools=["Read"]), }, )
Why decompose?

Each subagent runs in its own context window. The main agent doesn't have to hold a code review and a test plan in its head — it just dispatches and synthesises the returned bullets.

Heads-up

AgentDefinition is the one place the Python SDK keeps camelCase fields (disallowedTools, mcpServers) — and it must be the dataclass, not a plain dict.

8hooks
Hooks — intercept every tool call

A PreToolUse hook for observability (log every call) and another for safety (block rm/sudo). Pure async functions in your process.

control PreToolUse HookMatcher
▸
Run it
$ make step-8
The deny hook
async def block_dangerous_bash(input_data, tool_use_id, context): cmd = input_data.get("tool_input", {}).get("command", "") or "" if re.search(r"\brm\b", cmd, re.I) or re.search(r"\bsudo\b", cmd, re.I): return {"hookSpecificOutput": { "hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "rm/sudo not allowed in this demo.", }} return {} # continue normally options = ClaudeAgentOptions(hooks={"PreToolUse": [ HookMatcher(hooks=[log_tool_calls]), # every tool HookMatcher(matcher="Bash", hooks=[block_dangerous_bash]), # Bash only ]})
What you'll see

The agent writes notes.txt, then tries rm notes.txt. The hook prints its block line, the deny short-circuits before the shell ever runs, and the agent gets a tool result it can recover from.

Heads-up

The hook return value uses camelCase keys (hookSpecificOutput, permissionDecision) — the same wire format as the TypeScript SDK. Empty {} means continue.

9perms
Interactive permissions — the human in the loop

The "Claude wants to write pizza.txt — allow?" prompt, implemented in a small async callback.

control can_use_tool permission_mode
▸
Run it
$ make step-9
The callback
from claude_agent_sdk import PermissionResultAllow, PermissionResultDeny async def can_use_tool(tool_name, tool_input, context): answer = (await asyncio.to_thread(input, "[y]es / [n]o / [a]lways > ")).strip().lower() if answer in ("y", ""): return PermissionResultAllow(updated_input=tool_input) return PermissionResultDeny(message=f"User declined {tool_name}. Don't retry.") options = ClaudeAgentOptions( allowed_tools=[], # empty so EVERY call routes through can_use_tool can_use_tool=can_use_tool, permission_mode="default", # default / acceptEdits / plan / dontAsk / bypassPermissions )
Decision order
  • Is the tool in allowed_tools? — auto-run
  • Do PreToolUse hooks say deny? — block (step 8)
  • Else, call can_use_tool if present
  • Else default to deny
Heads-up

can_use_tool only returns allow/deny — the "ask" outcome belongs to hook output, not this callback.

The capstone — a meeting-notes agent

Composes built-ins + a skill + a hook into one useful agent. Reads transcripts/*.txt, writes formatted output/*.md.

capstone Glob · Read · Write setting_sources PreToolUse disallowed_tools
▸
Run it
$ make step-10
The whole thing
options = ClaudeAgentOptions( model="claude-sonnet-4-6", allowed_tools=["Glob", "Read", "Write"], # auto-approve these disallowed_tools=["Bash"], # actually remove the shell add_dirs=[str(TRANSCRIPTS_DIR), str(OUTPUT_DIR)], setting_sources=["project"], # scope skill discovery hooks={"PreToolUse": [HookMatcher(hooks=[log_tool_calls])]}, )
What it brings together

  • Skills (step 4) — meeting-notes-formatter drives the output shape

  • Tool restriction — disallowed_tools keeps it off the shell (because allowed_tools doesn't)

11alt sdk
Same ideas, different SDK + local model

PydanticAI with a local Ollama model. The agent ideas are portable; only the glue changes.

alt pydantic-ai OpenAIModel ollama
▸
Prerequisites
  • Ollama running locally: brew install ollama && ollama serve
  • A tool-capable model: ollama pull llama3.3 (or qwen2.5-coder)
Run it
$ make step-11
The provider setup
import os from pydantic_ai import Agent from pydantic_ai.models.openai import OpenAIModel from pydantic_ai.providers.openai import OpenAIProvider model = OpenAIModel( model_name=os.environ.get("OLLAMA_MODEL", "llama3.3"), provider=OpenAIProvider(base_url="http://localhost:11434/v1"), ) agent = Agent(model, system_prompt=system_prompt) # skills injected into the prompt @agent.tool_plain async def get_weather(city: str) -> str: """Get the current weather for a city.""" ...
What stays the same
  • System prompt, tools, and a loop
  • The skill discovery idea — but PydanticAI has no skill primitive, so skills.py rolls a tiny loader that reads .claude/skills/*/SKILL.md and concatenates them into the system prompt
Honest caveats

Local models are bounded at tool use. Small models (<30B) often hallucinate tool calls or skip them. No Anthropic key needed here. The Claude Agent SDK + Claude remains the production-quality default.
